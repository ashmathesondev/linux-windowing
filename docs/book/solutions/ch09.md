# Solutions, chapter 9

## Review questions

1. `cairo_image_surface_create_for_data` wraps existing memory. The surface does not own it, and Cairo writes pixels directly where you point it. The framebuffer format and stride are chosen to be exactly what Cairo expects.
2. The colour channels are stored already multiplied by alpha. 50 percent opaque pure green: alpha 0x80, green 0x80 (255 times 0.5), red and blue 0, so `0x80008000`.
3. A stroke is centred on the path. A one pixel line at an integer coordinate covers half of two rows, giving two half intensity rows. `strokeRect` insets the rectangle by half the line width so the stroke lies entirely inside the requested rectangle, which for odd widths and integer rectangles lands on whole pixels.
4. Logical extents are the layout box (line height and advance widths), ink extents are the tight bounds of the drawn glyphs. Use logical for layout so boxes do not change size with the particular letters used.
5. How many characters into the character at `index` the point was. A non zero value means it was past the middle (the nearest boundary is after that character), so you advance.
6. Cairo multiplies all coordinates by the scale before rasterising, so the application keeps using logical coordinates and the output has more detail. Lines and text are re-rendered at the higher resolution, not stretched.

## Exercises

**Ex 9.1** Rectangles (filled, stroked, rounded, rounded stroked, gradient, pill), circles (filled, stroked), lines (thick orange, thin green), triangle, a card with shadow, text at four sizes plus bold and italic, a multi script line, a measured box with a caret line, a clipped text sample.

**Ex 9.2**

```cpp
void Renderer::fillEllipse(float cx, float cy, float rx, float ry, Color c) {
    impl_->setColor(c);
    cairo_save(impl_->cr);
    cairo_translate(impl_->cr, cx, cy);
    cairo_scale(impl_->cr, rx, ry);
    cairo_new_path(impl_->cr);
    cairo_arc(impl_->cr, 0, 0, 1, 0, 2 * M_PI);
    cairo_restore(impl_->cr);   // restore BEFORE fill so line widths are not distorted
    cairo_fill(impl_->cr);
}
```

Restoring before the fill keeps the path (which is stored in device space) while undoing the transform. For a stroked ellipse this matters, because the stroke would otherwise be elliptical.

**Ex 9.3**

```cpp
void drawTextCentered(Renderer& r, Rect box, std::string_view t, const Font& f, Color c) {
    const TextSize s = r.measureText(t, f);
    r.drawText(box.x + (box.w - s.width) / 2, box.y + (box.h - s.height) / 2, t, f, c);
}
```

For a button: `w = s.width + 24`, `h = s.height + 12`.

**Ex 9.4** At scale 1, a width of 1 on integer coordinates is crisp because `strokeRect` insets by 0.5. A width of 2 or 3 also lands on whole pixels thanks to the inset of 1.0 or 1.5 (3 gives half pixel edges and looks softer). At scale 2 everything is sharper because each logical pixel is two device pixels, so odd widths land on whole device pixels.

**Ex 9.5**

```cpp
float fitFontSize(Renderer& r, std::string_view s, float maxWidth) {
    float lo = 4, hi = 200;
    for (int i = 0; i < 20; ++i) {
        const float mid = (lo + hi) / 2;
        if (r.measureText(s, Font{"Sans", mid}).width <= maxWidth) lo = mid; else hi = mid;
    }
    return lo;
}
```

Twenty iterations give precision far below a pixel.

**Ex 9.6**

```cpp
void Renderer::drawImage(float x, float y, int w, int h, const uint32_t* argb) {
    cairo_surface_t* img = cairo_image_surface_create_for_data(
        (unsigned char*)argb, CAIRO_FORMAT_ARGB32, w, h, w * 4);
    cairo_set_source_surface(impl_->cr, img, x, y);
    cairo_paint(impl_->cr);
    cairo_surface_destroy(img);
}
```

The pixel data must be premultiplied for translucent images. The pointer must stay valid until the surface is destroyed.

**Ex 9.7** Render a black rounded rect into an `OffscreenSurface` larger by the blur radius, blur rows then columns three times with a box of width about 0.6 times the sigma, and draw it with `cairo_mask_surface` using the shadow colour. The look is smoother than the layered version. Speed is slower the first time, so cache the result per size.
