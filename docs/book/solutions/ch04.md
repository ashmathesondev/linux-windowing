# Solutions, chapter 4

## Review questions

1. Keycodes: WASD movement in a game (position matters, not the letter). Keysyms: the Ctrl+C copy shortcut (the key that says C, wherever it is). Text: typing into a text field.
2. X keycode = evdev code + 8.
3. A `KeyRelease` followed at once by a `KeyPress` with the same `time` and `keycode`. The alternative is `XkbSetDetectableAutoRepeat`, after which the server sends only repeated presses.
4. It tracks modifier and group state. Without updates, Shift, Caps Lock and AltGr have no effect on symbols.
5. Buttons 6 (left) and 7 (right).

## Exercises

**Ex 4.1** For `Shift+a`: a `KeyPress` for Shift_L with empty text and mods `-`, then a `KeyPress` for `A` (sym `A`, text `"A"`, mods `Shift`), then releases in reverse or similar order. The sym for the second key is `A`, not `a`, because xkb_state saw Shift pressed. Plain `a` gives sym `a`, text `"a"`, mods `-`.

**Ex 4.2** With the server's keymap loaded once at start (`xkb_x11_keymap_new_from_device` is called only in `init`), a layout change after start is not noticed, so output stays on the old layout. A robust program listens for `XkbNewKeyboardNotify` and rebuilds the keymap and state. The platform layer in chapter 8 does this.

**Ex 4.3**

```cpp
case LeaveNotify:
    if (ev.xcrossing.mode == NotifyGrab) break;   // ignore
```

Press a button, drag outside: you get a Leave with mode grab at the start of the drag, which does not mean the mouse left in the sense your hover code cares about.

**Ex 4.4**

```cpp
Bool supported;
XkbSetDetectableAutoRepeat(dpy, True, &supported);
```

Call before the loop and delete the peek in the `KeyRelease` case. A held key now prints one release at the end and repeated presses in between (the repeat flag is no longer set by our code, because the server does not mark them, you would track "already down" yourself).

**Ex 4.5**

```cpp
bool isPrintable(const std::string& s) {
    for (unsigned char c : s) {
        if (c < 0x20 || c == 0x7f) return false;
    }
    return !s.empty();
}
```

Bytes of 0x80 and above are parts of multi byte characters, so they pass. A stricter version decodes code points and rejects C1 controls (U+0080 to U+009F).
