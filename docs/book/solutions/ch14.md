# Solutions, chapter 14

## Review questions

1. ImGui's own OpenGL backend needs only OpenGL 3.0 level features, and 3.3 is available on essentially all hardware and drivers, so a higher version would exclude machines for no gain. 4.6 offers, for example, compute shaders (4.3), direct state access (4.5), persistent mapped buffers (4.4), SPIR-V shaders and `glMultiDrawIndirect`. A 2D triangle renderer needs none of these.
2. The display is the connection to a graphics system (a GPU, or a compositor). The context holds OpenGL state: shaders, buffers, textures. The surface is where the pixels end up (a window or a pbuffer). The surface can be absent (`EGL_NO_SURFACE`) because the renderer draws into its own framebuffer object, which needs no EGL surface, if the driver has `EGL_KHR_surfaceless_context`.
3. It maps ImGui's logical coordinates (origin top left, y down, units up to `DisplaySize`) to clip space (-1 to +1). The second row has `2 / (B - T)`, positive, where a textbook OpenGL projection has `2 / (T - B)`. The textbook version puts the top of the screen at clip +1, which is the top for a window, but `glReadPixels` returns rows bottom first, so the readback would be upside down. With the flipped sign, the first row in memory is ImGui's top row.
4. Finding which pixels a triangle covers (edge functions and the fill rule), interpolating the vertex colour and the UV for each pixel (barycentric weights), blending the result with what is in the framebuffer (`glBlendFuncSeparate`), clipping to the scissor rectangle, and filtering the texture sample.
5. `fb.stride` is the number of bytes per row in the destination and can be larger than `width * 4`. `PACK_ROW_LENGTH` is in pixels, hence `stride / 4`. Without it, GL assumes tightly packed rows and the image appears sheared.
6. It adds `basevertex` to every index fetched from the index buffer. ImGui uses 16 bit indices, which can only address 65,536 vertices. When a draw list has more, ImGui splits it into several commands, each with a `VtxOffset`, and the backend declares that it handles it with `ImGuiBackendFlags_RendererHasVtxOffset`.
7. With the texture swizzle `{ONE, ONE, ONE, RED}`. Reading the texture in the shader returns `(1, 1, 1, r)` where `r` is the byte stored in the texture. Nothing in the shader changes.
8. Texture ids are created by the renderer that services the texture requests. A second renderer would receive the first one's id (a GL name or a pointer) and misuse it. The test builds the same UI twice, in two separate ImGui contexts, with a fixed time step and identical input, once per renderer, and compares the two snapshots.
9. When `EglContext::create` cannot make an OpenGL 3.3 core context (no EGL driver, no GPU, no software rasterizer). Because `SKIP_RETURN_CODE 77` is set in `tests/CMakeLists.txt`, CTest reports the test as skipped, and the run still passes.
10. `glReadPixels` waits until the GPU has finished all drawing, so the CPU and GPU run one after the other instead of overlapping, and it copies the whole frame from GPU memory to main memory (about 10 MB at 1920 x 1280), after which the window system copies it again to the compositor. A swap chain presents the GPU image directly with no copy through the CPU.

## Exercises

**Ex 14.1** After the loop: `#ifndef NDEBUG for (GLenum e; (e = g.GetError()) != NO_ERROR_;) std::fprintf(stderr, "GL error 0x%04x\n", e); #endif`. With the VAO unbound, `DrawElementsBaseVertex` in the core profile fails with `0x0502` (`INVALID_OPERATION`) and nothing is drawn.

**Ex 14.2** Keep `gallery.hpp` renderer neutral by adding a `const char* rendererDetails` string to `gallery::State` (an empty string for the CPU renderer) that `main` sets once at startup from `gl->glVersion()` and `gl->glRenderer()`, and print it with `ImGui::TextWrapped`. The gallery only sees a string.

**Ex 14.3** Two vectors, `std::vector<ImDrawVert>` and `std::vector<ImDrawIdx>`, are filled by appending each list. Remember for each list the starting vertex index `base`. Upload both once. For a command, draw with `basevertex = base + cmd.VtxOffset` and an index offset of `listIndexStart + cmd.IdxOffset`. It is faster when many small lists exist (many windows), because the number of buffer uploads drops from one per list to two per frame. On the gallery, which has a handful of lists, the difference is hard to measure; on llvmpipe uploads are memory copies, so expect little change. On a real GPU the number of synchronizations matters more.

**Ex 14.4** After the surfaceless attempt fails, `auto queryDevices = (PFNEGLQUERYDEVICESEXTPROC)eglGetProcAddress("eglQueryDevicesEXT"); EGLDeviceEXT devices[8]; EGLint n; queryDevices(8, devices, &n); display = getPlatformDisplay(EGL_PLATFORM_DEVICE_EXT, devices[0], nullptr);` then initialize as before. Check the client extension string for `EGL_EXT_device_enumeration` and `EGL_EXT_platform_device` first. Device zero is not always the GPU you want; loop over devices and prefer the one whose `EGL_VENDOR` string you recognize.

**Ex 14.5** Same shape as exercise 13.3: `glGenTextures`, `TexImage2D` with `RGBA8` and the pixels, `LINEAR`, return the GL name as an `ImTextureID`. At 3x, the GPU version is smooth because it filters bilinearly, while the CPU version (nearest) shows square texels. Adding bilinear sampling to the CPU renderer (exercise 13.4) makes them match again.

**Ex 14.6** Typical result on a real GPU: the shading and upload are small (the scene is a few thousand triangles) and the readback dominates, because 3840 x 2160 x 4 bytes is 33 MB per frame that must cross the PCIe bus and wait for the GPU. On llvmpipe there is no bus, and drawing itself dominates, which is the main reason it is not a good model of a GPU's performance. Measure with `Finish()` before and after `ReadPixels` to separate "waiting for the GPU" from "copying".

**Ex 14.7** `ww::Window` needs a way to expose its native handle (an `Display*` and `Window` on X11, a `wl_display*` and `wl_surface*` on Wayland) without leaking Xlib or Wayland headers, for example an opaque `NativeSurface { void* display; uintptr_t window; Backend kind; }`. `EglContext` gains a factory that takes it and creates the platform display (`eglGetPlatformDisplay`) and a window surface (`eglCreatePlatformWindowSurface`, with `wl_egl_window_create` on Wayland), and a `swap()`. `GlRenderer::render` binds framebuffer 0 when a surface exists and skips the readback and the FBO. Headless tests keep the FBO path through the surfaceless factory, so the existing tests still run in CI. A new test can only run where a display exists (use Xvfb).

**Ex 14.8** Shaders: first line `#version 300 es`, and a `precision mediump float;` line in the fragment shader. EGL: `EGL_OPENGL_ES_API` and `EGL_OPENGL_ES3_BIT`, and no profile mask. `gl33.hpp`: ES 3.0 has no `glDrawElementsBaseVertex` (it is in ES 3.2), so use `glDrawElements` and make sure draw lists stay below 65,536 vertices (drop `RendererHasVtxOffset`), or fall back to re-basing the indices on the CPU; and the read format `GL_BGRA` is not guaranteed in ES (`GL_RGBA` is), so read `RGBA` and swap the channels in a loop, or ask for `EXT_read_format_bgra`.
