# Solutions, chapter 12

## Review questions

1. State (a plain struct), a build function that describes the UI and applies actions, and a loop that waits for events, feeds the toolkit and draws only when needed.
2. The frames counter shown in the header does not change while you leave the window alone. `top` shows about 0 percent. With a focused text field it rises about twice a second (caret blink) and stops when focus leaves.
3. It feeds the real toolkit with the same event types a real window produces, and renders with the real renderer into memory. Only the platform layer is replaced.
4. The toolkit works out hot and active during drawing. A press and a move delivered before any frame has been drawn would not have established that the widget is active, so the move would not drag. A real application naturally has frames between events.
5. Real backend behaviour (X11 protocol, Wayland protocol, decorations) and real keyboards or IME. Cover them with scripted tests under Xvfb and headless weston, and manual checks on real sessions.

## Exercises

**Ex 12.1** Put `bool isValidEmail(std::string_view)` in `validation.hpp/.cpp`, test it in a plain `main` with `CHECK`s (empty, `a@b`, `a@`, `@b`, whitespace). In `build`, call it when Save is clicked and set `s.status = "Enter a valid email address"` plus a flag `s.error = true` that draws the label with a red colour (`LabelStyle` has no red, so use `ui.theme()` plus a new style or a custom colour parameter).

**Ex 12.2** Record the rectangles of Reset and of the fields (via `lastRect`) into extra members of `Settings` (or a `Rects` struct). The test types into the name field, clicks Reset, and checks `s.displayName == "Ash"` and that `s.status == "Reset to defaults"`.

**Ex 12.3** Press Tab once and check that the first focusable widget (the theme button in the gallery) is focused: press Space and verify `darkTheme` flipped. Press Tab again to move to the first tab header or next widget and check by activating it. Tab past the last widget and verify it wraps to the first.

**Ex 12.4** Go to tab 3, click the dropdown, call `key(Escape)`, then check `state.language` equals the previous value. Also open it, click an item, and check the change.

**Ex 12.5** Render with `savePng`, store a reference under `tests/golden/`, and write a compare function that loads both PNGs with Cairo (`cairo_image_surface_create_from_png`) and checks that every channel differs by at most, say, 3. It breaks when fonts change (system font update, different fallback fonts) or Cairo changes anti-aliasing, so pin fonts in CI or use golden images only for font free drawings.

**Ex 12.6** Add `using NowFn = std::function<Clock::time_point()>; void setClock(NowFn)` to `Context`, and replace every `Clock::now()` with `now()`. In the test, keep a `time_point t`, advance it by 600 ms, and check that `nextWakeupMs()` lies in `[1, 530]` and that the caret visibility computed from `elapsed % (2 * 530) < 530` flips. Typing calls `resetBlink`, so the next wake up is about 530 again.

**Ex 12.7** Valgrind typically reports "possibly lost" or "still reachable" blocks from fontconfig and glib (global caches) and no errors in our code. It can also report uninitialised reads that ASan cannot (MSan is the sanitizer for that). Use suppressions for the library noise.
