# Solutions, chapter 10

## Review questions

1. In your own variable, passed by reference to `ui.checkbox("label", value)`. The toolkit does not keep a copy.
2. To remember things across frames that belong to a particular widget: whether it is pressed, focused, its caret, its scroll offset. The id is the key into those tables.
3. Hot is under the mouse (highlight). Active is being pressed, and stays active until the button is released even if the mouse leaves. Focus receives the keyboard.
4. No. Press over the button sets `activeId_`. On release `clicked = hover`, and the mouse is not over it, so `clicked` is false. `activeId_` is reset to 0 either way.
5. The background is drawn before the children, so their total height is not known yet. The previous frame's measurement is used. `endFrame` notices a change and sets `needsRedraw_`, and `drawFrame` runs another pass (up to four) before presenting, so the user only ever sees the settled result.
6. Because inserting or deleting in the middle of a UTF-8 sequence produces invalid text. `prevBoundary` and `nextBoundary` and the clamping at the start of the widget keep positions on boundaries. `indexAtX` also returns boundaries.
7. `nextWakeupMs()` returns -1 when nothing needs a timer (sleep until an event), or the time to the next caret blink change when a text field has focus. The app passes it to `waitEvent`.

## Exercises

**Ex 10.1** Sketch:

```cpp
bool Context::toggleSwitch(std::string_view label, bool& value) {
    const Id id = makeId(label);
    const Rect r = allocate(40 + 8 + textWidth(displayText(label)), theme_.rowHeight);
    bool hover = false, held = false;
    bool clicked = clickBehavior(id, r, hover, held);
    registerFocusable(id);
    if (focused(id) && consumeKey(Key::Space)) clicked = true;
    if (clicked) value = !value;
    const Rect track{r.x, r.y + (r.h - 20) / 2, 40, 20};
    renderer_->fillRoundRect(track, 10, dim(value ? theme_.accent : theme_.track));
    const float knobX = value ? track.right() - 18 : track.x + 2;
    renderer_->fillCircle(knobX + 8, track.y + 10, 8, dim(Color::hex(0xffffff)));
    drawText({r.x + 48, r.y, r.w - 48, r.h}, displayText(label), dim(theme_.text), false);
    if (focused(id) && enabled()) drawFocusRing(track, 10);
    return clicked;
}
```

**Ex 10.2** Two `button("-")` and `button("+")` calls would share ids, so wrap in `pushId`. Clamp `value` after the buttons. The label can be a `label(std::to_string(value))`.

**Ex 10.3** Track `hoverStart` per id. When the same id is hovered for 600 ms, push an overlay with the tooltip. `nextWakeupMs` must return `min(existing, remaining hover time)` while a hover is pending. When the mouse moves, reset.

**Ex 10.4** In password mode, draw one bullet per UTF-8 character instead of the text, compute the caret from the bullet string, and disable Ctrl+C and Ctrl+X (cut would leak the text). Paste can stay.

**Ex 10.5** `collapsingHeader` is a button-like widget that toggles `open`. The content after it is `if (open) { ... }`. When it opens, the enclosing card grows by one frame late, and `drawFrame` repeats the pass so the card is the right size on the first presented frame.

**Ex 10.6** The model needs a list of lines (or one string with newlines and a function that maps index to line and column), vertical movement that remembers the desired column, a two axis scroll, and selection drawn as one rectangle per line. Cursor up: find the line and the x of the caret, then `indexAtX` on the previous line with the same x.

**Ex 10.7** Typing one character: 2 passes minimum (input), and possibly a third if a card changed. Moving the mouse over nothing: `hadInput` is true, so 2 passes, but nothing changes. You can optimise by comparing the mouse position to the last widget hit and skipping redraws when no hot id changed (this is a worthwhile exercise).
