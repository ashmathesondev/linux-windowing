# Solutions, chapter 3

## Review questions

1. A 32 bit id (an XID) naming an object that lives in the server. It is not a pointer. You pass it back in every request.
2. The window manager intercepts the map request, creates a frame window with the title bar and borders, reparents your window into it, and then maps the frame. Only then do you see it.
3. `WM_NAME` is the legacy Latin-1 property, `_NET_WM_NAME` is the UTF-8 one that modern window managers prefer. Setting both works with old and new managers.
4. `XFlush`, `XSync`, and any call that waits for a reply (including `XNextEvent` when the queue is empty).
5. Without it, the manager destroys the window and the server closes your connection. With it, you get a `ClientMessage` and decide when and whether to exit.

## Exercises

**Ex 3.1** Change `width`, `height`, `background`. `xwininfo` then click the window: "Width" and "Height" show the size. Note the reported size excludes the window manager's frame.

**Ex 3.2**

```cpp
XSelectInput(dpy, win, StructureNotifyMask | ExposureMask | KeyPressMask);
...
case KeyPress:
    if (XLookupKeysym(&ev.xkey, 0) == XK_Escape) running = false;
    break;
```

Include `<X11/keysym.h>`.

**Ex 3.3** `xprop _NET_WM_NAME` prints the UTF-8 string. Without `_NET_WM_NAME`, `XStoreName` takes Latin-1 so characters outside it come out wrong or garbled in the title bar.

**Ex 3.4** Create `win1` and `win2`, set `WM_DELETE_WINDOW` on both. In the loop, on a delete message: `XDestroyWindow(dpy, ev.xclient.window)`, decrement a counter, and stop when it reaches zero. Do not exit on the first.

**Ex 3.5** `XClassHint hint{(char*)"p01", (char*)"P01"}; XSetClassHint(dpy, win, &hint);`. Desktop environments use `WM_CLASS` to group windows, match them to launchers and apply per application rules.
