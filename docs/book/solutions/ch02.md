# Solutions, chapter 2

## Review questions

1. `IMPORTED_TARGET` bundles include directories, compile definitions and link flags into one target, and propagates them to anything that links it. The `_LIBRARIES` variables carry only library names, so you must also remember `_INCLUDE_DIRS` and `_CFLAGS_OTHER` yourself.
2. The result must not depend on which version of the protocol package a machine has. Vendoring pins the exact interface the code was written against.
3. Compiler and flag differences make object files incompatible. Separate directories avoid rebuilding everything every time you switch, and keep both results available.
4. `WAYLAND_DEBUG=1`.

## Exercises

**Ex 2.1** With `DISPLAY=` empty, X11 reports it could not connect (`XOpenDisplay(nullptr)` falls back to nothing). With `WAYLAND_DISPLAY=nonexistent`, `wl_display_connect(nullptr)` tries `$XDG_RUNTIME_DIR/nonexistent`, fails, and Wayland reports it could not connect. Each failure is independent.

**Ex 2.2** Add `#include <X11/extensions/XShm.h>`, and in the X11 branch:

```cpp
std::printf("MIT-SHM: %s\n", XShmQueryExtension(dpy) ? "yes" : "no");
```

In `p00_env_check/CMakeLists.txt` add `PkgConfig::XEXT` to `target_link_libraries`. Call it before `XCloseDisplay`.

**Ex 2.3** Use `cmake --preset clang-asan`, `cmake --build --preset clang-asan`, `ctest --test-dir build/clang-asan`. The test sets `ASAN_OPTIONS=detect_leaks=0` because fontconfig keeps global caches that LeakSanitizer reports; those are not bugs in our code. An off by one write to a `std::vector` or array makes ASan abort with `heap-buffer-overflow` and print a stack trace.

**Ex 2.4** The Xvfb screen is whatever you gave it (1280x800 in the example). Your real session reports its actual size. The point is that the program works unchanged on a display with no monitor.
