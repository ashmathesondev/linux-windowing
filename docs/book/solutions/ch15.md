# Solutions, chapter 15

## Review questions

1. The client must also send the caret rectangle (`set_cursor_rectangle`) so the input method can place its popup, and the surrounding text (`set_surrounding_text`), and enable and disable the text input as focus moves. Without the rectangle, the candidate window appears in a random place.
2. `wp-fractional-scale-v1` (tells the preferred scale) and `wp-viewporter` (lets a buffer of any size be shown at a given logical size).
3. A screen reader needs names, roles, states and bounds, not pixels. A toolkit that only draws has no object tree to expose. It must emit one itself each frame.
4. The UI context and everything above the `Renderer` interface. It only calls primitives such as `fillRoundRect` and `drawText`.
5. If `appId` does not match the `.desktop` file name (Wayland) or `StartupWMClass` (X11), the shell cannot associate the window with its launcher entry and uses a generic icon.

## Exercises

**Ex 15.1** Create the table once: `xkb_compose_table_new_from_locale(ctx, setlocale(LC_CTYPE, nullptr), XKB_COMPOSE_COMPILE_NO_FLAGS)`, a state with `xkb_compose_state_new`. For each key press feed the keysym with `xkb_compose_state_feed`. If the status is `XKB_COMPOSE_COMPOSING`, swallow the key. If `XKB_COMPOSE_COMPOSED`, take the result with `xkb_compose_state_get_utf8` and send it as a `TextEvent`. If `XKB_COMPOSE_CANCELLED`, reset. If `XKB_COMPOSE_NOTHING`, use the normal text. Compose, then `'`, then `e` should give `é`.

**Ex 15.2** Intern the `PRIMARY` atom, reuse the clipboard owner code with the atom as a parameter. Set ownership when a selection is made (the toolkit needs a callback `onSelectionChanged(text)`), and on a middle click read PRIMARY and insert at the click position.

**Ex 15.3**

```cmake
install(TARGETS p09_polish RUNTIME DESTINATION bin)
install(FILES packaging/p09.desktop DESTINATION share/applications)
```

The desktop file needs `Name=Account settings`, `Exec=p09_polish`, `Type=Application`, `Categories=Utility;`, and a name that matches `appId`, here `linux-windowing.p09`, so the file should be called `linux-windowing.p09.desktop`.

**Ex 15.4** Vendor `fractional-scale-v1.xml` and `viewporter.xml`, generate code, bind both globals, create a `wp_fractional_scale_v1` and a `wp_viewport` for the surface, handle `preferred_scale(uint)` (divide by 120.0), allocate buffers at the rounded pixel size, call `wp_viewport_set_destination(logicalW, logicalH)` and leave `buffer_scale` at 1. To test without hardware, use a compositor that lets you set a fractional scale (Weston, Sway with `output * scale 1.5`) and check with `WAYLAND_DEBUG=1` that buffers have the expected size.

**Ex 15.5** A good design page states: goal and non goals, the protocol or API involved, a diagram of the data flow, the change in each layer (platform, renderer, UI, tests), a test plan (what a headless test can cover, what needs manual checks), and the main risk (for example IME: compositors differ).
