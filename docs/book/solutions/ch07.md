# Solutions, chapter 7

## Review questions

1. The keymap is a large text (tens of kilobytes). A file descriptor avoids copying it through the socket buffer, and the compositor can share one memfd with every client.
2. The compositor tracks the true modifier and layout state, including things the client cannot see. It sends it in `wl_keyboard.modifiers`. Using key events as well would double count and drift (for example when a key was pressed before the window got focus).
3. The X server on X11 (the client sees repeated presses, or release plus press pairs). The client on Wayland, driven by a timer from `repeat_info`.
4. Synchronisation with the real display refresh (no tearing, no extra frames), and automatic throttling to zero when the window is hidden.
5. A client cannot know or set its absolute position. The compositor handles snapping, tiling and animations, and requires a serial proving a real user action started it.
6. Buffer: 1600 x 1200 pixels. `damage_buffer` takes buffer pixels (so up to 1600 x 1200). Pointer events use logical coordinates in the 800 x 600 space.

## Exercises

**Ex 7.1** GNOME prints "client-side (compositor has no xdg-decoration)". KDE prints "server-side". `wayland-info | grep decoration` shows `zxdg_decoration_manager_v1` on KDE and nothing on GNOME.

**Ex 7.2** The printed rate should match `repeat_info`, typically 25 to 40 per second after a 400 to 600 ms delay. Change it with `gsettings set org.gnome.desktop.peripherals.keyboard repeat-interval 20` on GNOME and reconnect the keyboard or restart the client to receive the new `repeat_info`.

**Ex 7.3** `BTN_LEFT` 0x110, `BTN_RIGHT` 0x111, `BTN_MIDDLE` 0x112, `BTN_SIDE` 0x113, `BTN_EXTRA` 0x114 (the usual back and forward buttons).

**Ex 7.4** If focus leaves while the timer is armed, no key release ever arrives for that window (the release goes to the new focus), so the timer keeps firing. `stopRepeat` in `onKeyboardLeave` disarms it.

**Ex 7.5** Keep `animating = mouseDown`. In the button handler set it and, if it became true, call `render(app, true)` to start the callback loop. In `onFrameDone` pass `requestNextFrame = animating`. When it is false no new callback is requested and the loop ends by itself. Commit only on input events otherwise.

**Ex 7.6** Typical places: computing buffer pixel size (`logical * scale_`), `wl_surface_set_buffer_scale`, `cairo_surface_set_device_scale`, creating the cursor theme at `24 * scale_`, and building the `ResizeEvent` that reports `scale` to the application. Each converts between logical coordinates used by the application and device pixels used by buffers.

**Ex 7.7** Add a region to the `Region` enum and `hitTest`, draw a button, and on click call `xdg_toplevel_set_maximized` or `unset_maximized` depending on the maximised state. The state comes from the `states` array in the toplevel configure event (`XDG_TOPLEVEL_STATE_MAXIMIZED`).
