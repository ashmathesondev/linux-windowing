# Solutions, chapter 8

## Review questions

1. The application keeps control of its loop and can integrate timers and idle behaviour in one place. Callbacks would force re-entrant handlers, make the order of events harder to reason about, and make testing harder.
2. Pixels are needed to size and index the buffer. Logical coordinates are the unit of layout and are independent of the monitor's density, so the UI code never changes between scale 1 and scale 2.
3. X11: `acquireFramebuffer` pumps events until `ShmCompletion` clears `shmInFlight_`. Wayland: `acquireBuffer` looks for a buffer that is not busy, with the release listener clearing the flag.
4. Nothing but a declaration of ownership and the formats on offer. The text is sent on demand to whoever pastes (X11 via property and `SelectionNotify`, Wayland via a file descriptor).
5. A hung or slow source would freeze the UI forever. The timeout bounds the damage and returns an empty string.

## Exercises

**Ex 8.1** On Wayland, resize events come once per configure and contain the new scale, and you see decorations (if on GNOME). On X11 under XWayland the scale is usually 1 unless `Xft.dpi` is set, and you see `Expose` driven redraws. With `WW_SCALE=2` the `ResizeEvent` reports double the pixel size for the same logical size on both backends.

**Ex 8.2** X11: send a `ClientMessage` of type `_NET_WM_STATE` to the root window with data `{_NET_WM_STATE_ADD (1), _NET_WM_STATE_FULLSCREEN, 0, 1}` and event mask `SubstructureRedirectMask | SubstructureNotifyMask`. Wayland: `xdg_toplevel_set_fullscreen(toplevel, nullptr)` and `unset_fullscreen`. In both cases the result arrives as a size change, so rely on the resulting resize event rather than assuming success.

**Ex 8.3** Add the enumerator in `window.hpp`. In `x11_window.cpp` create it with `XCreateFontCursor(dpy, XC_sb_h_double_arrow)` and add to `cursors_`. In `wayland_window.cpp` add a name list (`"ew-resize"`, then `"sb_h_double_arrow"`, `"h_double_arrow"`) to the cursor lookup. Update any switch that uses `Cursor`, including the UI layer that maps widgets to cursors.

**Ex 8.4** X11: `FocusIn` and `FocusOut` events. Wayland: `wl_keyboard.enter` and `leave`. Store a bool in each backend and return it.

**Ex 8.5** X11: `requestClipboardText` calls `XConvertSelection` and sets state `Waiting`; the `SelectionNotify` handler reads the property and pushes a `ClipboardEvent`. Wayland: create the pipe, send `receive`, add the read fd to the poll set, accumulate until EOF, then push the event. Both need a timeout timer and a way to cancel a stale request when a new one starts.

**Ex 8.6** A `NullWindow : ww::Window` with `std::deque<Event> script`, `waitEvent` popping from it and returning false when empty, `acquireFramebuffer` returning a vector backed buffer, and `present` counting calls. Add a way to create it, for example `Backend::Null` handled in the factory or simply construct it directly in the test. Direct construction needs no factory change.
