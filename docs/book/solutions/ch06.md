# Solutions, chapter 6

## Review questions

1. A `wl_surface` is a rectangle of pixels with no meaning. `xdg_toplevel` is a role given through `xdg_surface` that makes it a desktop window with title, size, close and window states.
2. A buffer implies a size and content, but the compositor has not yet decided the window state and size. The initial buffer-less commit asks the compositor to send the first configure. Attaching a buffer first is a protocol error.
3. The registry lists which optional features exist and at what versions, so the client adapts. X11 gives a fixed core protocol plus extensions you query individually.
4. After `wl_buffer.release` for that buffer.
5. All pending state (buffer, damage, scale, and so on) takes effect together, atomically, so the compositor never shows a half updated surface.
6. By design. The compositor owns layout, and exposing absolute positions would allow tracking other windows and enable spoofing. Clients get relative information only (for example during interactive move requests).

## Exercises

**Ex 6.1** Order: `bind` of `xdg_wm_base` (during registry roundtrip), then the first `commit` without a buffer, then `configure` events, then `ack_configure`, then the first `commit` with a buffer. So bind, empty commit, configure, buffer commit.

**Ex 6.2**

```cpp
std::printf("global %u: %s v%u\n", name, interface, version);
```

in `onGlobal`. The list matches `wayland-info` for the globals advertised.

**Ex 6.3** Replace `std::fill_n` with two loops: for each `y`, `row = data + y * stride_in_pixels`, fill `row[x]` with a colour computed from `x` and `y`.

**Ex 6.4** Typically `0 x 0` on the very first configure (compositor lets you choose), and non zero afterwards during resizes, maximise, tiling or when the compositor remembers a size. If it is 0, use your own default.

**Ex 6.5** `xdg_toplevel_set_maximized(app.toplevel)` is a request, so the compositor may or may not obey. If it does, the `states` array in the configure callback contains `XDG_TOPLEVEL_STATE_MAXIMIZED`. Iterate it with `wl_array_for_each(state, states)` and compare to the enum.

**Ex 6.6** Typical result: the compositor sends a protocol error (`xdg_surface` error, "buffer attached before initial configure") and closes the connection. `wl_display_dispatch` returns -1. `WAYLAND_DEBUG` shows the `error` event. The exact message depends on the compositor.
