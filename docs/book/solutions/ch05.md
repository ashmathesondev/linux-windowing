## Exercises

**Ex 5.1** Output reads `Transfer method: MIT-SHM` locally. Over `ssh -X`, `DISPLAY` begins with `localhost:` so the program (which looks for a leading `:`) selects `XPutImage`. The animation is slower and the CPU and network cost visibly higher.

**Ex 5.2** Inside `drawFrame` replace the per pixel colour with:

```cpp
const bool dark = ((x / 32) + (y / 32)) & 1;
row[x] = dark ? rgb(40, 40, 60) : rgb(200, 200, 220);
```

where `row = fb.pixels() + y * fb.stride()`.

**Ex 5.3** Make `Framebuffer fbs[2]` (heap allocated for resize) and `int inFlightIndex = -1`. Draw into `fbs[1 - inFlightIndex]` if one is in flight, present it, and set `inFlightIndex` to it. On `ShmCompletion`, clear it. You can now draw the next frame while the server reads the last. Note that on resize you must recreate both once neither is in flight.

**Ex 5.4** Count frames and print every second. Without vsync, expect close to 60 because of the timer. If lower, the per pixel loop in `drawFrame` (done in software, one pixel at a time) is the limit on a large window. Try a release build to see the difference.

**Ex 5.5** Keep a `bool dirty`. Set it on `ConfigureNotify`, `Expose` and `MotionNotify`. Replace the frame timer with `if (dirty && !inFlight)` and use `poll(..., -1)` when not dirty and not in flight. Remove the time dependent animation, or the window will look frozen.

**Ex 5.6**

```cpp
void drawLine(Framebuffer& fb, int x0, int y0, int x1, int y1, uint32_t c) {
    int dx = std::abs(x1 - x0), dy = -std::abs(y1 - y0);
    int sx = x0 < x1 ? 1 : -1, sy = y0 < y1 ? 1 : -1;
    int err = dx + dy;
    for (;;) {
        if (x0 >= 0 && x0 < fb.width() && y0 >= 0 && y0 < fb.height())
            fb.pixels()[size_t(y0) * fb.stride() + x0] = c;
        if (x0 == x1 && y0 == y1) break;
        int e2 = 2 * err;
        if (e2 >= dy) { err += dy; x0 += sx; }
        if (e2 <= dx) { err += dx; y0 += sy; }
    }
}
```

The bounds check per pixel is the clipping. A faster version clips the line segment to the rectangle first.
